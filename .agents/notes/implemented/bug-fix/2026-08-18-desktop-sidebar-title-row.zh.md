# Agent Note: 桌面侧边栏使用标题行

Status: implemented

[English](2026-08-18-desktop-sidebar-title-row.md) | 中文

## 问题

通过整体下移 Web 根节点为原生窗口控件 overlay 预留空间，也会从侧边栏扣除相同高度。工作区列表因此损失可用高度，但左侧栏并不会与另一侧的窗口控件冲突。单独上移侧边栏子树还会移动底部固定的设置区，而覆盖全宽的固定拖拽层会拦截侧边栏标题中的可点击控件。

## 决策

AppFrame 提供稳定的 `data-shell-*` 布局锚点及一个无 Web 表现的桌面拖拽区。桌面样式表按照原生 overlay 高度组合两条网格行：侧边栏跨越两行，会话栏与详情栏占据下方行，拖拽区则占据响应式侧边栏轨道之后、原生窗口控件之前的标题行。框架使用 `--dsw-specific-sidebar-fill` 绘制该行。

侧边栏保留现有 flex 所有权。设置区仍作为非滚动 footer 固定在 viewport 底部，工作区／会话区域获得新增的标题行高度，并继续使用单一滚动列表。共享的数值型标题栏高度同时配置 Electron overlay 与渲染层网格；Electron 的 Windows DPI 缩放使 CSS 像素保持设备无关。

## 考虑过的替代方案

**整体缩进根节点。** 这能让每一栏都避开原生控件，但会在侧边栏浪费相同高度并缩短其唯一滚动列表。

**向上平移侧边栏。** 移动完整子树也会移动设置区，或者需要补偿高度并可能在框架的 overflow 边界被裁切。

**保留固定拖拽 overlay。** 覆盖 viewport 的固定元素无法跟随侧边栏的折叠、默认及拖动宽度，并会拦截其下方的标题控件。

## 后果

桌面侧边栏获得一条标题行的列表容量，同时不改变底边、设置位置、滚动条所有权或响应式宽度计算。会话栏与详情栏保持原有上下位置。桌面标题行组合依赖 AppFrame 的稳定 data 锚点；Web 布局忽略隐藏的拖拽区。
